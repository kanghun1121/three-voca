# 문체·검증 표기 예시

이 예시는 톤과 검증 결과 구분 방식을 보여준다. 섹션 헤더는 이 예시 원문 그대로이며,
실제로 쓸 땐 이 저장소의 고정 템플릿(`연관 이슈`/`📝 작업 내용`/`🖼️ 스크린샷`) 헤더에
같은 문장 스타일을 담는다.

```markdown
## 변경 내용

기록을 저장할 때 버튼을 연속으로 누르면 같은 기록이 여러 번 생성되는 문제가 있었습니다.
저장 요청이 진행되는 동안 버튼을 비활성화하고 로딩 상태를 표시하도록 변경했습니다.

저장에 실패하면 입력한 내용을 유지하고 버튼을 다시 활성화해 재시도할 수 있도록 했습니다.

## 확인

- 저장 버튼을 연속으로 눌러도 요청이 한 번만 전송되는지 테스트 통과
- 저장 실패 후 입력 내용 유지 및 재시도 테스트 통과
- 실기기에서의 동작은 아직 확인하지 못했습니다.
```

## 이 예시에서 따라야 할 것

- 첫 문단이 "무엇이 달라지는지"부터 시작한다 — 문제 현상(연속 탭) → 변경(비활성화+로딩) → 실패 시
  동작(입력 유지+재시도)까지 순서대로, 각 문장이 새 정보를 담는다. 방식을 고른 이유나 대안은 없다.
- "안정성을 개선했습니다" 같은 뭉뚱그린 표현 대신 실제로 바뀐 동작을 그대로 썼다.
- 검증 항목을 "테스트 통과"와 "아직 확인하지 못했습니다"로 명확히 구분했다. 실기기 확인을 안 했으면
  안 했다고 쓰고, 확인한 것처럼 얼버무리지 않았다.
- 대화용 문구("아래는 작성한 PR입니다" 등)나 마무리 인사가 없다.

## 이 저장소 템플릿에 옮길 때

```markdown
## 연관 이슈

<#이슈번호>

## 📝 작업 내용

- 저장 버튼 연속 탭 시 같은 기록이 여러 번 생성되는 문제 수정
- 저장 요청 중 버튼 비활성화 + 로딩 상태 표시
- 저장 실패 시 입력 내용 유지, 버튼 재활성화로 재시도 가능

## 🖼️ 스크린샷 (선택)

연속 탭 시 요청이 한 번만 전송되는지, 실패 후 재시도가 되는지 테스트로 확인. 실기기 동작은
아직 확인하지 못함.
```

문장형 문단이었던 "변경 내용"이 이 저장소 관례대로 목적별 불릿으로 바뀌었을 뿐, 순서·근거·검증
구분은 그대로다.
