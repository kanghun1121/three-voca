# TVC-ASSERT: 결함을 구별하는 단언

적용: 기대값, 테스트 입력, 오류 처리 또는 단언이 변경된 경우.

- [ ] 기대값을 프로덕션 변환 함수와 독립적으로 정했는가? 같은 함수를 양쪽에서 호출하면 같은 결함을 공유하지 않는가?
- [ ] 반환값·상태·저장 결과 등 관찰 가능한 효과를 확인하는가? 구현을 잘못 바꾸면 어느 단언이 실패하는가?
- [ ] 오류의 종류와 필요한 코드를 확인하는가? 넓은 `catch`, `try?`, 단순한 non-nil 검사가 다른 오류도 성공 처리하지 않는가?
- [ ] 정렬·조합·매핑 테스트 입력의 값이 구별되는가? 순서를 뒤집거나 항목을 빠뜨려도 결과가 같아지지 않는가?

계약이 단지 오류 발생 여부나 호출 횟수만 요구한다면 그 단언으로 충분할 수 있다. 테스트 이름과 기존 단언만으로 계약을 가정하지 말고 호출부와 검증 대상을 확인한다.
