# Test Value Check 예시

## TVC-VALUE

첫 번째 뜻을 검증한다면서 뜻 하나만 가진 입력을 쓰고, 같은 입력·단언의 테스트를 두 개 추가하면 첫 항목 선택 오류를 잡지 못하며 중복 유지 비용만 늘어난다. 뜻이 다른 항목을 둘 이상 사용하고 하나의 테스트에서 첫 번째 값을 확인한다.

## TVC-ASSERT

404 응답의 계약을 검증한다면 `catch { XCTAssertNotNil(error) }`는 디코딩 오류도 통과시킨다. 기대 오류 타입과 상태 코드를 직접 확인한다.

## TVC-PATH

ViewModel 로딩 테스트에서 `requestIfNeeded`를 제거하고 fixture를 직접 검사하면 로딩 경로가 망가져도 통과한다. 외부 응답만 주입하고 실제 메서드를 호출해 결과 상태를 확인한다.

## TVC-ASYNC

스트림 값을 기다리며 `Task.sleep(50ms)` 후 단언하면 느린 실행 환경에서 실패할 수 있다. 필요한 값이 관찰될 때까지 기다린 뒤 단언한다.
