# TVC-PATH: 검증 대상 경로와 의존성

적용: 프로덕션 메서드 호출, Mock, `withDependencies`, fixture 사용 또는 테스트 전용 API가 변경된 경우.

- [ ] 테스트가 이름에 적힌 프로덕션 메서드와 검증할 경계를 실제로 통과하는가?
- [ ] Mock은 외부 의존성만 대체하는가, 검증할 동작까지 대신 구현하는가?
- [ ] SUT를 만들기 전에 올바른 계약에 의존성을 주입했는가? 필요한 인자·순서·횟수는 관찰 가능한가?
- [ ] 의도하지 않은 호출이 기본 Mock의 임의의 성공값이나 조용한 no-op에 가려지지 않는가?
- [ ] 테스트용 공개 메서드·분기·상태 setter가 제품 코드에 추가됐는가? 기존 주입 경로로 같은 동작을 검증할 수 있는가?
- [ ] Example용 `happyPath`·`emptyPath`와 테스트 데이터가 해당 사용처에 있는가? Interface 계약으로 퍼졌다면 의존성 주입 기준을 확인한다.

fixture 자체가 검증 대상이라면 fixture 검사도 의미 있다. 반면 로드·상태 전이를 검증한다고 하면서 fixture나 setter의 값만 검사하면 그 경로의 회귀를 놓친다. 테스트 전용 API는 접근 수준만 낮출지보다 제거할 수 있는지를 먼저 검토한다. 경계 자체가 검증 대상이면 그 경계를 Mock으로 대체하지 않는다.
