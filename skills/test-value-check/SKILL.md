# Test Value Check

테스트 이름이나 개수만으로 판단하지 않는다. 변경 전후의 테스트가 어떤 프로덕션 경로를 실행하고 어떤 결함을 발견할 수 있는지 확인한다. 추가된 줄과 삭제된 호출·단언을 함께 읽는다. 테스트 계획에서는 실행할 경로와 발견하려는 결함을 확인한다.

## 검토 자료

- 중복·필요성: `references/test-value.md`
- 기대값·오류·정렬 단언: `references/assertions.md`
- 대상 경로·Mock·주입·테스트 전용 API: `references/execution-path.md`
- 비동기 완료·시간 의존: `references/async-stability.md`
- 판단에 사례가 필요할 때: 해당 ID의 `references/examples.md`

여러 문제가 겹치면 관련 자료를 함께 읽는다. 체크리스트는 조사할 질문이며 위반 목록이 아니다.

## 피드백

조치할 가치가 있는 발견 사항에만 검증하려는 동작, 실패 조건, 현재 테스트가 결함을 놓치는 이유, 작은 보완 방법을 적는다. 실행하지 않은 테스트가 통과·실패했다고 주장하지 않는다. 테스트가 없다는 이유만으로 코멘트를 만들지 않는다. 리뷰 출력의 우선순위와 형식은 별도의 리뷰 정책을 따른다.
