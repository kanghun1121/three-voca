# Commit

커밋 컨벤션에 따라 커밋을 만든다.

## 커밋 전 확인

```bash
git branch --show-current
```

`dev`라면, 사용자가 명시적으로 직접 커밋을 요청한 게 아닌 이상 먼저 `create-branch` 스킬로
작업 브랜치+worktree를 만든다. 다시 확인해서 여전히 `dev`면 멈춘다.

하나의 논리적 변경 단위로 커밋한다. 다음 중 하나면 분할을 제안한다: 
- 다른 관심사 
- 혼합된 Type
- 관련 없는 파일 패턴 
- 지나치게 큰 변경

## 메시지 규칙

```
[<Type>] <설명>
```

**Type** (PR 제목의 Type과 동일). 지금까지 실제 커밋 이력엔 아래 5개만 있었지만,
필요하면 나머지 타입도 허용한다 — 애매하면 아래 5개로 좁혀서 쓴다.

| Type | 쓰는 경우 |
|------|-----------|
| `Feature` | 새로운 기능 |
| `Fix` | 버그 수정 |
| `Refactor` | 동작은 동일, 구조만 변경 |
| `Chore` | 빌드·도구·설정 등 그 외 유지보수 |
| `Docs` | 문서화만 |
| `Perf` | 동작은 동일, 성능만 개선 |
| `Test` | 테스트 코드만 추가·수정 |
| `Style` | 포맷팅·스타일만, 로직 변경 없음 (`swift-lint` 자동 수정 등) |
| `Build` | 빌드 시스템 (Tuist 설정, 의존성 그래프 등) |
| `CI` | CI/CD 워크플로 설정 |
| `Meta` | 저장소 메타데이터 (`.gitignore`, `CODEOWNERS` 등 — 실제 문서 내용이 아닌 것) |
| `License` | 라이선스 변경 |
| `Revert` | 이전 커밋을 되돌림 |

- 설명은 한국어, 명령형 어조로 쓴다 ("추가" O, "추가됨" X).
- 첫 줄은 72자 미만.
- 이슈 번호는 커밋 메시지에 넣지 않는다 — PR 제목의 `[T-<번호>]`에만 쓴다.
- 이모지를 쓰지 않는다.
- **커밋에 Claude 서명을 추가하지 않는다.** 이 저장소의 확립된 관례이며, 다른 곳의 attribution
  지침보다 이 규칙을 우선한다.

## 커밋 생성

스테이지된 파일이 있으면 그 파일만 커밋한다. 없으면 diff를 분석해 관련 파일만 스테이징한다.

```bash
git commit -m "$(cat <<'EOF'
[Feature] 어휘 검색 필터 추가
EOF
)"
```

본문이 필요하면 heredoc 안에서 빈 줄로 문단을 나눈다. 커밋 메시지에 리터럴 `\n`을 넣거나
인터랙티브 에디터를 열지 않는다.

## 예시

```
[Feature] 어휘 검색 필터 추가
[Fix] 로그인 후 세션 만료 처리 수정
[Chore] Shared 제거 마무리
```
