# OEC-STATE: 상태와 데이터 흐름

적용: 화면 상태의 소유·수명, 전역 Store, 상태 복제 또는 전이 구조가 변경된 경우.

- [ ] 한 화면에서만 필요한 상태를 앱 전역 Store로 옮겨 다른 화면·세션까지 수명을 늘렸는가?
- [ ] 같은 서버 데이터의 여러 사본을 맞추려고 별도의 이벤트 전달·동기화 계층을 추가했는가?
- [ ] 로딩·내용·오류 같은 유한한 화면 단계를 표현하려고 범용 상태 머신이나 이벤트 프레임워크를 추가했는가?
- [ ] 기존 화면 상태와 새 상태 객체가 같은 값을 중복 보관해 모든 전이마다 둘을 갱신해야 하는가?

여러 화면에서 실제로 공유하거나 복원해야 하는 상태라면 공유 구조가 필요할 수 있다. 원본과 관찰자를 구분하는 SSOT 기준을 확인하고, 단순화가 필요한 공유·복원 동작을 잃지 않는지 살핀다. 화면 수명과 데이터 원본을 확인하지 못했다면 질문으로 남긴다.
