# 코드 리뷰 우선순위

리뷰 에이전트는 조치가 필요한 발견 사항에 `P1`, `P2`, `P3` 중 하나를 붙인다. 등급은 문제의 종류가 아니라 **이번 변경의 영향과 수정 시점**으로 정한다. 코멘트 수를 채우기 위해 발견 사항을 만들지 않는다.

| 등급 | 판단 기준 | 처리 |
| --- | --- | --- |
| P1 | 재현 조건과 근거가 분명한 중대한 문제. 데이터 유실, 보안 노출, 중복 결제, 핵심 기능 오동작 등 | 병합 전 수정 권고 |
| P2 | 현재 동작, 설계 또는 테스트의 신뢰성을 실제로 해치는 문제. 영향은 P1보다 제한적 | 이번 변경에서 수정하거나 유지 이유 설명 권고 |
| P3 | 현재 동작은 가능하지만 이번 변경에 불필요한 복잡성이나 유지 비용을 더한 경우. 현재 비용과 더 작은 대안을 설명할 수 있어야 함 | 병합을 막지 않는 선택적 개선 |

각 코멘트에는 **발생 조건, 영향 또는 현재 비용, 변경 줄에서 확인되는 근거**를 적는다. 테스트가 핵심 경로를 우회해 주장한 동작의 회귀를 잡지 못한다면 해당 위험에 맞춰 평가한다. UseCase나 Interface의 존재, 테스트의 부재, 체크리스트 항목에 해당한다는 사실만으로 등급을 매기지 않는다.

근거가 부족한 의심은 P3으로 낮춰 게시하지 않는다. 확인이 필요한 사항은 요약에 불확실성으로 남긴다. 명확한 발견 사항이 없다면 라인 코멘트를 작성하지 않는다.
