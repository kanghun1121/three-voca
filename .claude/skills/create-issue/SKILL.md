# create-issue

새 GitHub 이슈 생성부터 문제정의 파일을 쓸 수 있는 상태까지 한 번에 준비한다. 기존 이슈 번호를 이미 갖고 있는 경우(`#87` 등)는 이 스킬이 아니라 CLAUDE.md의 "Starting From an Issue" 흐름(`setup-worktree` 직접 실행)을 따른다 — 이 스킬은 이슈 자체가 아직 없을 때만 쓴다.

## 실행 절차

### 1단계 — 이슈 정보 확인

다음이 필요하다:

- **제목** (필수) — 사용자가 안 줬으면 물어본다.
- **type** (필수) — feature, fix, refactor, chore, docs 중 하나. 제목/맥락으로 판단되면 확인만 받고, 애매하면 물어본다.
- **본문** (선택) — 짧아도 된다. 상세 내용은 이슈 본문이 아니라 3단계에서 만드는 문제정의 파일에서 다룬다. 본문을 억지로 길게 지어내지 않는다.

### 2단계 — 이슈 생성

```bash
gh issue create --title "<title>" --body "<body>"
```

출력된 URL 끝의 숫자를 이슈 번호로 파싱한다.

### 3단계 — setup-worktree 실행

`setup-worktree` 스킬을 이 이슈 번호로 바로 실행한다 (0단계 "이슈 확인"은 방금 만든 이슈라 내용을 이미 알고 있으므로 `gh issue view` 없이 그대로 이어가도 된다).

**단, setup-worktree의 3단계(문제정의 파일 생성)는 이 스킬에서는 다르게 동작한다**: 방금 만든 이슈는 아직 상세 내용이 없는 게 정상이므로, 이슈 제목/본문을 부풀려서 채우지 않는다. 대신 아래 스켈레톤만 쓰고 본문은 비워서 사용자가 직접 쓰게 한다.

```markdown
# <이슈번호> — <제목>

- 이슈: <이슈 URL>
- 생성일: <YYYY-MM-DD>

---

## 문제 정의

<!-- 여기에 도메인 문제를 작성하세요 -->
```

### 완료 안내

setup-worktree의 기존 완료 안내에 이어서, 문제정의 파일 경로를 강조해서 알려준다:

```
✅ 이슈 #<번호> 생성 + 작업 환경 준비 완료

  이슈     : <이슈 URL>
  브랜치   : <task-id>  (← dev)
  문제정의 : .harness/problems/<이슈번호 3자리>-<도메인제목>.md  ← 여기에 도메인 문제를 적어주세요

작성 후 harness-plan 스킬로 계획을 시작하세요.
```

## 하지 않는 것

- 문제정의 파일 본문을 대신 채우지 않는다 — 이슈 제목만으로 도메인 문제를 추측해서 적으면 CLAUDE.md의 "Do not invent production data" 원칙과 같은 문제가 생긴다(내용을 지어내는 것).
- PLAN.md, 테스트 계획 등 이후 단계(harness-plan/harness-test)의 산출물은 이 스킬의 범위가 아니다.
